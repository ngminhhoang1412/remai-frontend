# remai-frontend

Web client for **remai**, a Notion-like notes app (MVP). React 19, Vite, TypeScript, react-router and plain CSS.

Behaviour is specified in [`../remai-central-specs`](../remai-central-specs) (OpenSpec change `add-notion-core`; hosting in `adopt-flutter-and-serverless`). This repo has no copies of the specs. See [AGENTS.md](AGENTS.md) for where each spec lives.

Capabilities implemented here: `web-client`, plus the client-facing parts of `user-auth`, `page-management`, `page-content`, `page-search` and `page-trash`.

## Requirements

- Node.js 22.22+ or 24.x (developed on Node 24.11, npm 11)
- A running [remai-backend](../remai-backend) for real use. Tests don't need it, because they mock `fetch`.

## Setup

```sh
npm install
# optional: point at a backend that isn't on the default URL
echo "VITE_API_URL=http://localhost:8080" > .env.local
npm run dev            # http://localhost:5173
```

### Environment

| Variable | Default | Meaning |
|---|---|---|
| `VITE_API_URL` | `http://localhost:8080` | Base URL of remai-backend, without a trailing slash. Read at build time, as with all `VITE_*` variables. |

`.env.example` documents the variable. `.env` and `.env.*` files are git-ignored, except `.env.example`. The backend's CORS allowlist (`REMAI_CORS_ORIGINS`) must include the origin the app is served from. Its default is `http://localhost:5173`, which is why the dev server uses `strictPort` on 5173.

## Scripts

| Script | What it does |
|---|---|
| `npm run dev` | Vite dev server on port 5173 |
| `npm run build` | `tsc -b` type-check, `vite build` into `dist/`, then `scripts/write-headers.mjs` writes `dist/_headers` (see [Hosting](#hosting-cloudflare-pages)) |
| `npm run preview` | Serves the production build |
| `npm test` | Vitest (jsdom + Testing Library), single run |
| `npm run test:watch` | Vitest in watch mode |
| `npm run lint` | `tsc -b --noEmit`, then ESLint (typescript-eslint, react-hooks, react-refresh) |

## Layout

```
src/
  api/         wire types (mirror docs/api/openapi.yaml) and the fetch client
  lib/         pure logic: block rules, slash filtering, tree, autosave controller, helpers
  session/     token + user context, RequireAuth / PublicOnly route guards
  pages/       page-tree context (list, create, trash, optimistic title/icon)
  shell/       app shell: sidebar + tree, drawer, top bar, search dialog
  editor/      block editor (textarea per block) and slash menu
  views/       routes: sign-in/up, home, page, trash
  ui/          small shared components (modal, menu, emoji picker, icons, auto-growing textarea)
  test/        test setup, fetch mock and in-memory fake backend
```

Routes: `/login`, `/register`, `/` (home), `/p/:pageId`, `/trash`.

## Hosting (Cloudflare Pages)

The app is a static site on Cloudflare Pages (design D7 of the `adopt-flutter-and-serverless` change). There are no Pages Functions. `wrangler.toml` sets `pages_build_output_dir = "dist"`.

### What the build produces

- **`dist/_headers`** is generated by `scripts/write-headers.mjs` after `vite build`:
  - On every path: a `Content-Security-Policy` with scripts, styles, images and fonts from `'self'` only, `connect-src 'self' <origin of VITE_API_URL>`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'` and `frame-ancestors 'none'`. Also `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and `Cache-Control: no-cache`, so a reload always picks up a new deploy.
  - On `/assets/*` (fingerprinted files): `Cache-Control: public, max-age=31536000, immutable`, replacing the `no-cache` above.
  - The script resolves `VITE_API_URL` the same way Vite does (`.env*` files for the mode, then the process environment), so the CSP always matches the API URL baked into the bundle. If the variable is unset it falls back to `http://localhost:8080` with a warning, as the app does. If the value isn't an absolute `http(s)` URL, or contains credentials, the build fails. Pass `--mode <mode>` to the script if you build with `vite build --mode <mode>`.
  - No `'unsafe-inline'` is needed for styles: React `style={…}` props and `el.style.x = …` go through the CSSOM, which CSP doesn't restrict. Only `style="…"` attributes in HTML or set with `setAttribute('style', …)` are blocked, and the app has none.
- **Deep links** (`/p/<id>`, `/trash`, a reload on any route) use Pages' built-in single-page-app fallback: when the output has no top-level `404.html`, any path that isn't a file is answered with `index.html` and status 200. There is deliberately **no** `_redirects` file. Pages ignores `/* /index.html 200` as an infinite loop, and `/* / 200` would also shadow `/assets/*`. The build fails if `dist/404.html` exists, because it would turn deep links into 404s.
- HTTPS: Pages serves `*.pages.dev` and custom domains over HTTPS and redirects HTTP to HTTPS. For a custom domain, also turn on **Always Use HTTPS** in the zone's SSL/TLS settings.

### Check it locally

```sh
VITE_API_URL=http://localhost:8080 npm run build
npx wrangler@4.147.0 pages dev dist --port 8788      # emulates _headers and the SPA fallback
curl -I http://127.0.0.1:8788/p/00000000-0000-4000-8000-000000000000   # 200, text/html, CSP, no-cache
curl -I http://127.0.0.1:8788/assets/<file>.js                          # immutable cache
```

To use the app at `http://127.0.0.1:8788`, the backend's `REMAI_CORS_ORIGINS` must include `http://127.0.0.1:8788`. No Cloudflare account is needed for `pages dev`.

### Deploy with the CLI

```sh
VITE_API_URL=https://<api-id>.execute-api.<region>.amazonaws.com npm run build
npx wrangler@4.147.0 login                     # once
npx wrangler@4.147.0 pages deploy dist --project-name remai --branch main
```

`--branch main` makes it a production deployment (the production branch is set when the project is created). Any other branch name makes a preview deployment.

### Deploy with Git integration

In the Cloudflare dashboard: **Workers & Pages → Create → Pages → Connect to Git**, then pick this repo and set:

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Build output directory | `dist` |
| Environment variable `NODE_VERSION` | `24` (or 22.22+) |
| Environment variable `VITE_API_URL` (Production) | the prod API URL |
| Environment variable `VITE_API_URL` (Preview) | the **staging** API URL |

`VITE_API_URL` is read at build time, so changing it needs a rebuild (**Retry deployment**).

### Previews and CORS

The API's CORS allowlist has no wildcards (`platform-hosting` spec), so the random per-deployment hostnames (`<hash>.remai.pages.dev`) are never allowed. Instead:

- Preview builds point at the **staging** API (`VITE_API_URL` for the Preview environment).
- Staging's `CorsOrigins` lists the stable **branch alias** of the preview, e.g. `https://staging.remai.pages.dev` for the `staging` branch. Open previews through that alias, not through the per-commit URL.
- Production's `CorsOrigins` lists only the production origins (`https://remai.pages.dev` and any custom domain).

Rollback: in the dashboard, open **Deployments** and use **Rollback** on an earlier production deployment.

## Notes

- **Autosave** (design D10): 800 ms debounce, one save in flight per page, and another save follows if you edit during one. Pending changes are flushed when you leave a page, when the tab is hidden, and before sign-out or trashing. The status reads `Saving…`, `Saved` or `Couldn't save – retrying` (backoff 2 s → 30 s). Content goes through `PUT /pages/{id}/blocks` and title/icon through `PATCH`.
- **Security**: the session token lives in `localStorage` (see design Risks). User content is only ever rendered as text, and ESLint forbids `dangerouslySetInnerHTML`. The client never sends a token after sign-out, and any 401 from an authenticated call signs out.
- **Layout**: one breakpoint at 768 px. Below it the sidebar becomes an overlay drawer, and the page has no horizontal scroll down to 360 px.
